# Метка 113 — EMA shift фильтр + фикс настроек Стратегий 2/3 (июль 2026)

**Тег:** `metka-113`

## Что вошло

### АлгоТрейдинг — EMA shift фильтр в панели «Данные» (Multichart)

- Две независимые линии EMA-фильтра: период, сдвиг `%`, выбор ТФ (или текущий).
- Сетап валиден, когда точка входа (не `pt4`) выше обеих включённых EMA для лонга
  и ниже — для шорта. Один чекбокс → фильтр по одной линии.
- EMA берётся на баре входа; HTF считается агрегацией уже загруженных свечей
  (`aggregateCandlesToTf` в `js/indicators/htf-loader.js`, без сетевых запросов).
- Логика в копии `js/algo-trading/pattern-ema-filter.js` — оригинал Pattern 1-2
  не тронут.
- Фильтр применяется к клиентскому анализу: панель «Данные» и сканер тикеров.
  Движок живого бота EMA не использует — арминг сетапов без изменений.

### Настройки Стратегий 2/3 — фикс сохранения (Multichart + Algo Bot)

Числовые поля Стратегий 2 и 3 сбрасывались в сохранённые значения: опрос статуса
бота (каждые 2.5 с) безусловно перезаписывал `input.value` до того, как событие
`change` (blur / Enter) успевало сохранить ввод.

- Опрос больше не трогает поле под курсором (`isFieldBeingEdited`).
- Флаг `running` при монтировании берётся из статуса бота, а не из localStorage —
  залипший после краша `true` больше не блокирует правки.
- Блокировка полей при работе бота смотрит на свою стратегию (`getPrefs().running`),
  а не на любую запущенную — как это всегда делала Стратегия 1.

Правка перенесена в `bot-app/site-bundle/js/algo-trading/bot-strategy-ui.js`
(файлы Multichart и Algo Bot совпадают).
