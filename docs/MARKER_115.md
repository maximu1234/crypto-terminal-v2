# Метка 115 — все ТП Стратегий 2/3 выставляются сразу (август 2026)

**Тег:** `metka-115`

## Что вошло

### Финальный ТП — позиционный, ТП1/ТП2 — лимитки

Раньше при заливке частичной стратегии бот вешал на позицию только СЛ и ставил ТП
последовательными reduce-only лимитками. Из-за обрезки `orderLinkId` до 36 символов
ТП2 и ТП3 получали тот же id, что ТП1, и биржа отклоняла их как дубли — на позиции
оставался один ТП1. При быстром движении остаток позиции оставался без выхода.

- `attachStops(sym, slPrice, tpPrices[2])` — финальный ТП теперь позиционный
  (режим Full) и закрывает весь остаток с первой секунды, как и СЛ.
- Reduce-only лимитками остаются только ТП1 и ТП2, объём каждой — floor по своей
  доле от начального объёма позиции.
- `meta.tpPrice` для Стратегий 2/3 заполняется ценой финального ТП; для сетапов,
  открытых до обновления, цена берётся из последнего уровня `tpPrices`.
- `orderLinkId` для лимиток: короткий детерминированный хеш отпечатка + индекс ТП
  + nonce, всегда уникален в пределах 36 символов.
- В `positionMissingStops` убрано исключение для частичных стратегий: пропавший
  СЛ **или** ТП восстанавливается общим путём `attachStops`.
- Пропавшая лимитка ТП1/ТП2 восстанавливается в сверке (`ensurePartialTpLimits`),
  уже живые ордера переиспользуются по `orderLinkId`, id или близости цены.

### Снятие reduce-only лимиток

- При закрытии позиции (стоп, ручное закрытие) недоисполненные ТП1/ТП2 снимаются
  в `reconcileClosedEntries`.
- В периодической сверке снимаются лимитки-сиротки по уже полученным спискам
  позиций и ордеров — без дополнительных REST-запросов, работает и после
  перезапуска приложения с потерянной метой.
- Запуск бота, `stopPatternEngine` и аварийная остановка снимают алго-лимитки RO
  по символам без открытой позиции. Лимитки на открытых позициях остаются — это
  активные выходы.

### Сопутствующие фиксы

- Взятие ТП считается по закрытому объёму и фактическим объёмам лимиток
  (`meta.tpQtys`), а не по «пропавшему» `orderId`: ордер мог быть снят извне, и
  бот тогда считал ТП взятым и не восстанавливал его. Проценты долей для этого не
  годятся — объём округляется вниз по шагу инструмента.
- Перенос трейлинг-СЛ ботом больше не выглядит ручной правкой: снимок позиции в
  том же цикле ещё содержит старый СЛ, из-за чего выставлялся
  `stopsManagedByUser` и бот перестал бы управлять стопами (и восстанавливать ТП).
- `leavesQty` в `mapOrderRow` (`algo-bybit-rest.cjs`) — корректный остаток
  частично исполненной лимитки.
